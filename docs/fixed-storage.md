# 固定工作库与重启验证

主库固定为 项目根目录下的 data/desktop。用户级定位文件为 ~/.autominer/workspace.json（避开 AppData 虚拟化），根目录 autominer.workspace.json 为项目默认位置。显式 --data-dir 优先，供隔离试运行使用；隔离运行不会改写用户定位文件。

之前相同 AppData 路径在 Codex 包装环境与原生桌面程序中映射至不同文件，导致复制和升级后看起来恢复、重启又回到旧数据。整合时应以运行进程实际打开的数据库快照及对应运行密钥作为一份来源，另一份来源为需要导入的完整工作库。先在 data/storage-backups 保留两份数据库、DPAPI 密钥和配置，再按记录 ID 合并到固定目录。整合后应确认所有账号与模型凭证可解密，不向目标重放检查。

旧 release 下的 AutoMiner.exe 入口统一更新为修复版本，原二进制保留为 AutoMiner.legacy。所有入口读取相同用户定位文件，并受同一个工作库文件锁约束。原 AppData 目录保留作历史副本，不再作为默认写入位置。

启动行为：检查完整性；已登记库丢失时停止；已有账号/模型但保护密钥丢失时停止；启动前将数据库、密钥、配置和存储标识配套备份至 data/desktop/backups/startup-*。API、网关和模型服务启动时核对相同存储标识。界面“当前数据位置”可查看路径与标识。

不要只比较路径字符串或文件内容来认定桌面已修复；必须检查实际桌面 API 的数据目录、存储标识、博客目标、证据数量和凭证解密，并经由实际 EXE 重启复核。
